# Security Policy

## About This Project

This repository contains the website and related configuration for Andrew Jourdan, an independent sales and marketing representative working with consumer technology brands.

Security reports concerning this repository, its website, or its deployment configuration are welcome.

## Supported Versions

| Version | Security Support |
| --- | --- |
| Current production version | Supported |
| Previous versions | Evaluated on a case-by-case basis |
| Unmaintained versions | No guaranteed security updates |

Security fixes will generally be applied to the current production version.

## Reporting a Vulnerability

**Please do not publicly disclose an unpatched security vulnerability.**

### Preferred method: GitHub Private Vulnerability Reporting

If private vulnerability reporting is enabled for this repository, submit your report through GitHub's private reporting workflow:

https://github.com/andrewjourdan/andrewjourdan/security/advisories/new

This channel is preferred because it allows vulnerability details to be shared privately with the repository maintainer. If GitHub does not offer a private reporting option, do not post exploit details, credentials, personal information, or other sensitive information in a public issue. Instead, use a verified private contact method published by the repository owner.

- Repository: https://github.com/andrewjourdan/andrewjourdan
- Website: https://andrewjourdan.com/

### Information to include

Please include as much of the following information as you can safely provide:

- **Summary:** A concise description of the suspected vulnerability.
- **Affected component:** The relevant file, page, endpoint, configuration, or dependency.
- **Impact:** What an attacker might be able to do.
- **Reproduction steps:** Minimal steps to reproduce the issue.
- **Evidence:** Relevant logs, screenshots, or proof-of-concept details, with secrets and personal information removed.
- **Suggested remediation:** A proposed fix or mitigation, if known.

Do not access another person's account or data to prove a vulnerability.

## Delivery and Response Process

Please deliver reports privately through the reporting channel described above.

After receiving a report, the maintainer will make reasonable efforts to:

1. Review the report and determine whether it describes a reproducible security issue.
2. Assess its potential impact and urgency.
3. Investigate and develop an appropriate fix or mitigation.
4. Verify the fix before deployment, where practical.
5. Communicate relevant progress or resolution when the report includes a usable contact method.
6. Coordinate public disclosure after the issue has been addressed or the risk has otherwise been considered.

Response and remediation times depend on severity, complexity, and the information provided. No specific response or resolution deadline is guaranteed by this policy.

## Responsible Disclosure

Please allow a reasonable opportunity to investigate and address a reported vulnerability before publicly disclosing technical details.

Please do not:

- Access, modify, or disclose data belonging to other people.
- Disrupt website availability or business operations.
- Perform destructive testing or denial-of-service attacks.
- Use phishing, social engineering, or physical attacks.
- Retain, download, or share sensitive information beyond what is reasonably necessary to demonstrate the issue.

Only test systems and resources you are authorized to assess.

## Scope

Reports may concern security weaknesses in:

- This repository's source code and configuration.
- The production website at https://andrewjourdan.com/.
- Website deployment and domain configuration related to this project.
- Third-party dependencies or integrations where the issue directly affects this project.

Third-party services are independently operated. When appropriate, report issues in those services through their own security-reporting channels.

## Out of Scope

The following are generally not considered security vulnerabilities on their own:

- Automated scanner output without a reproducible security impact.
- Missing security headers without a demonstrated risk.
- General best-practice recommendations that do not identify a practical vulnerability.
- Social engineering, physical attacks, or denial-of-service testing.
- Issues in unrelated third-party services.

## Policy Updates

This policy may be updated as the project, website, and reporting procedures evolve.
